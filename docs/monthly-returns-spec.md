> 한 줄 요약: 2000년 이후 현재까지 **지수 월(月) 단위 수익률**을 조회·시각화하는 기능. **저장 원천은 일봉(daily)**, 월수익률·요약통계는 조회 시 월말 리샘플링으로 도출한다. 본 문서는 타당성 분석 + 규격서.

> - **스코프 = (a) 지수 수익률** (개별종목·전략백테스트는 본 범위 제외)
> - **대상 시리즈 5종 = 코스피 + 코스닥 + 미국 3대 지수(다우존스·S&P500·나스닥종합)**
> - **데이터 원천 = Yahoo 일봉(`interval=1d`).** 실호출로 5종 모두 2000-01 도달·단일 호출 수급 확인(§3.1). 단 KOSDAQ만 2000-10부터.
> - **저장 모델 = `DailyIndexPrice`(일봉).** 월수익률·MDD·주간 등 파생지표는 이 일봉에서 도출.

## 0. 개정 배경 (2026-07-01)

- 초판은 **월봉(`interval=1mo`) → `MonthlyReturn` 모델** 방식으로 백엔드 1~2단계를 구현했다.
- 사용자 재검토 결과 **일봉 원천으로 전환(방안 B)** 결정. 근거:
  1. **MDD(최대낙폭)는 일봉이 있어야 산출 가능** — 월봉 close만으로는 월중 저점이 소실되어 계산 불가. 초판 §6에서 MDD를 "후속"으로 미뤄둔 제약이 일봉 원천에서는 데이터 재수집 없이 해소된다.
  2. **정확한 월말 종가** — 일봉에서 각 월의 마지막 거래일 close를 직접 도출(월봉 close 근사에 의존하지 않음).
  3. **확장성** — 주간/임의구간 수익률, 롤링 수익률 등이 동일 일봉에서 파생 가능.
- **채택하지 않은 대안**: (A) 월봉 유지=MDD 영구 포기, (C) 일봉+월봉 병행 저장=동기화 부담·과설계.
- **폐기 대상**: 초판에서 구현된 `MonthlyReturn` 모델 및 `scripts/backfill-monthly-returns.ts`는 본 개정에서 걷어낸다(§4, §8 참조). `src/lib/monthly-returns.ts`의 **요약통계·API 응답 스키마는 재사용**한다.

## 1. 기능 개요 / 목적

- **목적**: 장기(2000~현재) 월별 수익률을 표·차트로 보여줘, 퇴직연금 가입자가 자산의 장기 성과·계절성·하락기 패턴을 직관적으로 파악하도록 한다.
- **핵심 산출물**: "연 × 월" 히트맵 표(행=연도, 열=1~12월, 셀=월 수익률%) + 누적수익률 라인차트 + 요약 통계(CAGR·최고/최저월·양봉비율 + **MDD**).
- **"월 수익률" 정의(공통)**: 특정 월 `m`의 수익률 = `(월말종가(m) / 월말종가(m−1)) − 1`. **월말 = 그 달의 마지막 거래일 종가**(일봉에서 도출). 전월말→당월말이 표준이며 인접 월 연쇄가 누적수익률과 정합.
- **MDD 정의**: 구간 내 일봉 종가 기준 최대낙폭 = `min_t( close_t / running_max(close_≤t) − 1 )`. 일봉이 있어야 산출 가능.

## 2. 스코프 (★확정 — (a) 지수 수익률)

> **사용자 결정: (a) 지수 수익률.** (b)/(c)는 채택하지 않으며 향후 별도 스펙으로만 검토.

| 후보 | 대상 | 2000년 도달 | 난이도 | 판정 |
|---|---|---|---|---|
| **(a) 지수 수익률** | 코스피·코스닥·다우·S&P500·나스닥종합 | **확인됨** (Yahoo 일봉 `interval=1d`) | **낮음** | ✅ **채택** |
| (b) 개별 종목 수익률 | 특정 종목(예 005930) | 부분 가능 | 중 | 후속 옵션(미채택) |
| (c) 전략/포트폴리오 백테스트 | 스크리너 필터·대가 13F 등 | **불가(2000)** | 높음 | 별도 과제(미채택) |

**근거**
1. **데이터가 2000년까지 즉시·정확하게 확보됨** — Yahoo chart API는 지수의 일봉(`interval=1d`)을 상장 이래로 제공한다. 추가 외부 의존 없이 기존 수집 패턴(`scripts/backfill-index-history.ts`) 재사용.
2. **생존편향·시점성 함정이 없음** — 지수는 단일 연속 시계열이라 (b)(c)의 구조적 리스크(상장/폐지/구성종목 변경)를 회피.
3. **기존 자산과 정합** — `IndicatorRecord(type)`·`REALTIME_SYMBOLS`·`backfill-index-history.ts`가 이미 일봉을 다룬다. 본 기능은 그 패턴을 `period1=2000-01-01`로 확장.
4. **(c)는 본질적으로 다른 기능** — 백테스트는 시점성 구성종목·과거 재무 필요. DART(`StockFinancial`)·13F(`GuruHolding`)는 최근 분기만 보유 → 2000년 백테스트는 현 데이터로 불가.

## 3. 데이터 가용성 분석

### 3.1 소스: Yahoo Finance chart API (지수 일봉) — **실측 완료 (2026-07-01)**

- 요청: `interval=1d&period1={2000-01-01 Unix초}&period2={현재}&includePrePost=false`.
  - **`period1`/`period2` 명시**가 핵심. `range=max`는 일부 지수에서 timestamp 누락 사례가 관측되므로 사용하지 않는다.
  - 응답: `chart.result[0].timestamp[]` + `indicators.quote[0].close[]`. 지수는 `adjclose ≈ close`라 close로 충분.
- **단일 호출로 26년 전체 수급 확인** (`query1.finance.yahoo.com/v8/finance/chart`, `interval=1d&period1=946684800`):

  | 시리즈 | Yahoo 심볼 | 일봉 count | 일봉 최초일 | 2000년 도달 |
  |---|---|---|---|---|
  | 코스피 | `^KS11` | 6,624 | 2000-01-04 | ✅ |
  | **코스닥** | `^KQ11` | (2000-10~) | **2000-10** | ⚠️ 2000-01~09 부재 |
  | 다우존스 | `^DJI` | ~6,600 | 2000-01 | ✅ |
  | S&P500 | `^GSPC` | 6,662 | 2000-01-03 | ✅ |
  | 나스닥종합 | `^IXIC` | ~6,600 | 2000-01 | ✅ |

  - **데이터량**: 5종 × ~6,600 ≈ **약 33,000행**. PostgreSQL 기준 소량. 백필 fetch는 시리즈당 1회(총 5회), 응답만 월봉보다 큼(호출 수는 동일).
  - **유일한 결손**: 코스닥 2000-01~09(Yahoo가 ^KQ11을 2000-10부터 제공). 시리즈별 `firstAvailable` 메타로 노출, 결손 구간은 UI 비표시.
  - "미국 3대 지수"는 **나스닥 종합(^IXIC)** 기준(^NDX 아님).

- **월말 리샘플링 규칙**: 각 (series, 연-월)에 대해 그 달의 **최대 date**를 가진 일봉 close를 월말 종가로 채택. 거래소 로컬 벽시계로 연/월 귀속(월 경계 밀림 방지 — `meta.gmtoffset` 반영, 기존 월봉 스크립트와 동일 원칙).

### 3.2 (b) 개별 종목 제약 (후속 스코프)
- 생존편향(폐지·합병 조회 불가), 티커/액면분할 보정, 종목선택 UI 비용 → MVP 제외.

### 3.4 AGENTS.md 제약과의 관계

## 4. 데이터 모델 (★개정 — 일봉 `DailyIndexPrice`)

### 채택: 신규 모델 `DailyIndexPrice`

```prisma
model DailyIndexPrice {
  id     String   @id @default(cuid())
  series String   // "KOSPI" | "KOSDAQ" | "DOW" | "SP500" | "NASDAQ"
  date   DateTime // 거래일 (UTC 자정 정규화, 거래소 로컬일 기준)
  close  Float    // 종가

  @@unique([series, date])
  @@index([series, date])
}
```

- **월수익률·MDD·주간 등은 저장하지 않고 조회 시 도출**(파생값 중복 저장 회피).
- **`IndicatorRecord` 재사용 안 함**: 일봉 라이브 cron(`collectRealtimeData`)이 당일 1포인트를 upsert하고, `backfill-index-history.ts`가 같은 type을 `deleteMany` 후 재삽입한다. 26년 히스토리를 섞으면 라이브/백필 사이클과 충돌(§초판 §4.1 지적) → **전용 테이블로 분리**해 라이프사이클 독립.
- **폐기**: 초판 `MonthlyReturn` 모델 및 `@@unique([series, yearMonth])` 인덱스는 스키마에서 제거. `scripts/backfill-monthly-returns.ts` 삭제.

### 마이그레이션 주의
- 프로젝트는 `prisma/migrations`가 비어 있고 관례상 **`prisma db push`**로 스키마를 반영해 왔다(초판 백엔드도 db push 사용). `MonthlyReturn` 제거 + `DailyIndexPrice` 추가를 db push로 반영. 정식 baseline 마이그레이션이 필요하면 별도 지시.

## 5. API 규격

```
GET /api/returns/monthly?series=KOSPI&from=2000-01&to=2026-06
```
- **파라미터**
  - `series` (필수): `KOSPI|KOSDAQ|DOW|SP500|NASDAQ`
  - `from`,`to` (선택): `YYYY-MM`. 기본 `from=2000-01`, `to=현재월`
  - (후속) `base`: 해외지수 원화환산 — MVP 미지원(원지수 그대로)
- **처리**: `DailyIndexPrice`에서 `[from월초, to월말]` 일봉을 읽어
  1. 월별 마지막 거래일 close로 **월말 종가 시계열** 구성,
  2. 인접 월 종가비로 **월수익률**,
  3. 요약통계(CAGR·best/worst·positiveRatio) + **MDD(일봉 종가 기준)** 산출.
- **응답(JSON)**
```jsonc
{
  "series": "KOSPI",
  "firstAvailable": "2000-01",     // 소스 최초월(시리즈별 상이)
  "rows": [
    { "yearMonth": "2000-01", "close": 952.0, "returnPct": null },
    { "yearMonth": "2000-02", "close": 884.0, "returnPct": -7.14 }
  ],
  "summary": {
    "cagrPct": 6.1,
    "bestMonth": {"ym":"2020-04","r":11.0},
    "worstMonth": {"ym":"2008-10","r":-23.1},
    "positiveRatio": 0.57,
    "mdd": {"pct": -54.5, "peak": "2007-10-31", "trough": "2008-10-24"}  // 신규(일봉 기반)
  }
}
```
- 응답 스키마·요약통계 로직은 초판 `src/lib/monthly-returns.ts`를 **재사용**(입력이 저장된 `MonthlyReturn` → 리샘플링된 월시계열로 바뀔 뿐). `mdd`만 신규 추가.
- 쿼리스트링 방식이라 Next.js 16 동적 라우트 `params` Promise 제약 해당 없음.

### 백필 / 갱신
- **백필 스크립트**: `scripts/backfill-daily-index.ts`(신규, 1회성·멱등 upsert). `interval=1d&period1=2000-01-01~period2=현재`. 심볼 매핑: KOSPI=^KS11, KOSDAQ=^KQ11, DOW=^DJI, SP500=^GSPC, NASDAQ=^IXIC. `BATCH=20` 병렬 upsert, insert/upsert-only(deleteMany 없음).
- **월 라이브 갱신**: 기존 일일 cron 종가를 `DailyIndexPrice`에 매일 1행 upsert(당일 거래일). 월말 별도 처리 불필요 — 조회 시 리샘플링이라 항상 최신.

### 6.3 컴포넌트별 구현

1. **히트맵 `ReturnsHeatmap` — 순수 HTML `<table>`**
   - Tailwind 스타일. 셀 배경은 **발산형 컬러스케일**: 음수=적 / 0=중립 / 양수=녹. 강도 = `Math.min(|r|/15, 1)` clamp 후 alpha(§고정 스케일 ±15%, 시리즈 바꿔도 색 의미 일관).
   - **접근성**: 색만으로 정보 전달 금지 → **셀에 수익률 숫자 병기**, 어두운 배경엔 흰 글자로 대비 확보. `<th scope>`로 연/월 헤더.
   - 결손월(코스닥 2000-01~09, 미래월)은 `—` 회색.
   - 우측 "연간" 열 = 그 해 월수익률 복리 누적.
2. **요약 카드 `SummaryCards`** — 기존 `IndicatorCard` 톤 재사용. MDD 카드는 peak→trough 날짜 부기. `summary.mdd`는 **옵셔널**로 취급(백엔드 2단계 반영 전엔 미표시).
3. **누적 차트 `CumulativeChart` (Recharts)** — 월말 종가 정규화(시작=100). **로그축 토글**(26년 장기라 선형축은 초반이 눌림). MDD 구간은 `ReferenceArea` 음영.
4. **컨트롤 `ReturnsControls`** — 시리즈 드롭다운 + 기간 프리셋(2000~ / 최근10년 / 최근5년). `router.replace`로 searchParams만 갱신.

### 6.4 모바일 전략 (메모리 규칙: Playwright 실측 검증 필수)

- **채택: 가로 스크롤** — 히트맵 `overflow-x-auto`, 연도 열 `sticky left-0` 고정. 데스크톱과 동일 컴포넌트로 "한눈에 계절성" 가치 보존. (세로 리스트 폴백은 계절성 패턴을 잃어 미채택.)
- 요약 카드는 2열 그리드로 래핑, 차트는 폭 100%.

### 6.5 결정 (확정)

- **비교 모드**: MVP는 **단일 시리즈**(히트맵은 본질적으로 1시리즈). 5종 멀티라인 비교는 후속.
- **컬러 스케일**: **고정 ±15%**(데이터 상대 스케일 아님).

## 9. 결론 (한 줄)

원천을 **일봉(`DailyIndexPrice`)**으로 전환하면 월별 수익률 기능은 그대로 제공하면서 **MDD·주간·임의구간 확장이 데이터 재수집 없이 열린다.** 실측상 5종 2000년 일봉이 단일 호출로 수급되며(~33k행, PG엔 소량), 초판의 요약통계·API 스키마는 재사용된다. 폐기 대상은 `MonthlyReturn` 모델/월봉 백필뿐이다.
